# 분석 질문 설계 (2단계)

## 먼저 확인

`산출물/1_결정할일.md`가 없으면 `decision-frame`부터 하자고 제안한다. 결정할 일 없이 질문을 만들면 요약으로 끝난다.

## 절차

1. **넓힌다.** 결정할 일에 답하는 데 필요한 분석 질문 10개를 만든다. 여섯 가지 입구에 고르게 걸치게 한다.
   - 지금 잘하고 있는가 (비교 기준, 추세와 분포)
   - 어디에서 문제가 생기는가 (지표 분해, 단계별 이탈)
   - 누구에게 무엇이 다른가 (집단 비교, 세분화)
   - 왜 이런 일이 생겼는가 (가설 비교, 정성 자료 연결)
   - 무엇을 먼저 해야 하는가 (영향 · 비용 · 위험)
   - 바꾼 것이 효과가 있었는가 (실험, 비교집단)
2. **거른다.** 질문마다 세 조건을 표로 판정한다.
   - 답할 수 있다: 주제별 표나 원천의 어느 파일·열로 답하는지 적을 수 있는가
   - 비교가 들어 있다: 무엇과 비교하는지 적혀 있는가
   - 답에 따라 행동이 달라진다: 답이 A면 무엇을, B면 무엇을 하는지 말할 수 있는가
3. **사용자에게 고르게 한다.** 세 조건을 다 통과한 질문 중 2개를 사용자가 고른다. 대신 고르지 않는다. 추천은 이유와 함께 하나만.
4. **질문 카드를 쓴다.**

## 출력

`산출물/2_질문카드.md`

```markdown
# 질문 카드
결정할 일: (1단계 한 줄 그대로)

| # | 분석 질문 | 입구 | 비교 기준 | 필요한 자료(파일·열) | 답이 A면 / B면 |
|---|---|---|---|---|---|
| 1 | | | | | |
| 2 | | | | | |

## 버린 질문과 이유
-
```

## 지킬 것

- 막연한 질문("고객은 무엇을 원할까")은 분석 질문으로 고쳐 쓴 버전을 옆에 제시한다.
- `원천파일_정의서.md`에 없는 자료가 필요하면 "지금 없는 자료"라고 표시한다. 없는 자료를 있다고 가정하지 않는다.
