# 분석 전 데이터 점검 (03 사실 만들기)

계산을 먼저 하면 틀린 숫자가 그럴듯하게 나온다. 하루상점 주문 데이터는 중복 120행을 그대로 두면 9월 매출이 392백만 원, 지우면 383백만 원이다. 그래서 숫자를 세기 전에 다섯 가지를 본다.

## 먼저 확인

- 어떤 파일로 무엇을 계산하려는지 한 줄로 받는다. 없으면 묻는다.
- `원천파일_정의서.md`(열 뜻)와 `마트_설계.md`(사람이 정한 기준)를 읽는다. 설계서의 기준이 계산 기준이다. 없으면 무엇을 매출로 셀지부터 묻는다.

## 절차

1. **기계 점검을 돌린다.**
   ```bash
   python3 <이 스킬 폴더>/scripts/profile.py 주문_정리본.csv --key 주문번호 --date 주문일시
   ```
   행 수, 열마다 빈칸 수, 완전히 같은 행, 키 중복, 날짜 범위와 달마다 행 수, 숫자 열의 최솟값과 음수를 낸다. 파일마다 돌린다(키가 없는 집계 파일은 `--key` 없이).
2. **다섯 가지로 정리한다.**
   - 구조: 행 하나가 무엇인가(주문 한 건, 하루 × 집단 요약 등). 이걸 틀리면 합계와 평균이 다 틀린다
   - 결측: 어느 열에 몇 개, 전체의 몇 %. 빈칸이 우연인지 규칙인지(특정 기간, 특정 경로에 몰리는지)
   - 중복: 완전히 같은 행인지, 키만 같고 값이 다른지. 몇 행이 어느 기간에 몰리는지
   - 기간 경계: 시작과 끝 날짜, 빠진 날이나 달, 비교할 두 기간의 길이가 같은지
   - 지표 정의: 설계서의 기준과 데이터가 어긋나는 곳(예: 매출에 배송비를 넣을지, 비율을 합계로 낼지 행 평균으로 낼지)
3. **처리 전후 차이를 보여 준다.** 중복을 지우면, 빈칸을 묶으면 핵심 숫자가 얼마나 달라지는지 한 줄씩(예: 9월 매출 392 → 383백만 원).
4. **멈추고 묻는다.** 지울지, 묶을지, 그대로 둘지는 사람이 정한다. 답을 받기 전에는 데이터를 고치지 않는다.

## 출력

`산출물/3_데이터점검.md`

```markdown
# 데이터 점검
파일: / 행 하나: / 기간:

| 점검 | 결과 | 처리 제안 | 처리 전후 차이 |
|---|---|---|---|
| 구조 | | | |
| 결측 | | | |
| 중복 | | | |
| 기간 경계 | | | |
| 지표 정의 | | | |

## 사람에게 묻는 것
1.
```

## 지킬 것

- 원본 파일은 고치지 않는다. 처리한 데이터가 필요하면 코드로 만들고 코드는 `산출물/코드/`에 남긴다.
- "문제 없음"도 결과다. 확인한 항목은 0건이어도 적는다.
- 이 스킬은 점검까지만 한다. 결정할 일이나 원인은 묻지 않는다.
