# 기술과 비교 (03 사실 만들기)

같은 숫자도 무엇과 비교하느냐에 따라 좋고 나쁨이 바뀐다. 이 스킬은 질문 하나에 숫자로 답하되, 기준과 분포와 차이의 크기를 함께 낸다. 원인 판단은 하지 않는다.

## 먼저 확인

- 질문을 한 줄로 받는다. 질문이 없으면 묻는다.
- `마트_설계.md`의 기준을 따른다. `산출물/3_데이터점검.md`가 있으면 거기서 정한 처리(중복 제거 등)를 그대로 쓴다. 점검을 안 했으면 data-check부터 하자고 한 줄 제안한다.

## 질문별로 내는 것

| 질문 | 내는 것 | 자주 틀리는 곳 |
|---|---|---|
| 얼마나 | 평균, 중앙값, 구간별 비중 | 평균만 말하면 소수의 큰 값이 대부분의 모습을 가린다 |
| 어떻게 변했나 | 전월, 전년 같은 달, 목표 대비를 한 표에 | 기준을 하나만 고르면 좋고 나쁨이 기준에 따라 뒤집힌 걸 놓친다. 기간 길이를 맞춘다 |
| 어디서 빠지나 | 단계마다 앞 단계 대비 비율, 두 기간 나란히 | 하루 비율을 평균 내지 않는다. **합계 ÷ 합계** |
| 누가 다른가 | 집단별 같은 지표, 차이를 %p와 %로 따로 | "18%p 떨어졌다"와 "23% 떨어졌다"를 섞지 않는다 |
| 차이가 우연인가 | 두 비율 검정의 p값과 차이의 범위 | 유의하다 = 우연은 아니다. 원인이라는 뜻이 아니다 |

## 절차

1. 질문을 위 다섯 중 무엇인지로 분류한다. 둘 이상이면 나눠서 답한다.
2. 계산은 코드로 하고 `산출물/코드/`에 남긴다. 비율 검정과 분포는 스크립트를 써도 된다.
   ```bash
   python3 <이 스킬 폴더>/scripts/stats.py prop <성공1> <전체1> <성공2> <전체2>
   python3 <이 스킬 폴더>/scripts/stats.py dist 주문_정리본.csv "상품 금액" --dedup 주문번호 --date 주문일시 --month 2026-09 --bins 20000,40000,60000,80000,100000,150000
   ```
3. 중요한 숫자 하나는 다른 방법으로 한 번 더 센다(예: 퍼널 합계와 주문 수). 다르면 멈추고 보고한다.
4. 설계서나 강의에 맞춰 볼 숫자가 있으면 대조한다(예: 9월 매출 약 383백만 원, 9월 신규 결제 완료율 약 61%).

## 출력

`산출물/3_기술비교.md` (질문이 여럿이면 질문마다 한 칸)

```markdown
# 질문: (한 줄)
비교 기준: (무엇과)

| 집단/기간 | 값 | 기준 | 차이(%p) | 차이(%) |
|---|---|---|---|---|

- 사실 문장: (숫자 + 기간 + 집단 + 기준을 한 문장에)
- 우연인가: (p값, 표본 수. "우연은 아니다"까지만)
- 다시 센 숫자: (무엇을 어떻게, 일치 여부)
- 코드: 산출물/코드/…
```

## 지킬 것

- 사실만 쓴다. "신규 고객이 떠나고 있다"는 해석이라 쓰지 않는다.
- 원인, 제안, 결정은 쓰지 않는다. 그건 04에서 결정할 일과 함께 한다.
- 표본이 작으면(집단 n이 100 미만 등) 숫자 옆에 n을 같이 적는다.
