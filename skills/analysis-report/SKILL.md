# 분석 리포트 한 장 (03 사실 만들기, What까지)

분석 리포트는 "데이터가 말하는 것"을 다른 사람이 다시 확인할 수 있게 적은 한 장이다. 판단을 바꿀 이유(So what)와 할 일(Now what)은 04의 인사이트 리포트가 한다.

**이 스킬의 한계 (일부러 둔 것):** 결정할 일을 묻지 않는다. 그래서 숫자는 맞지만 "그래서 쿠폰을 늘릴까, 배송비를 되돌릴까?"에는 답하지 못한다. 그게 03의 끝이자 04의 출발점이다. 사용자가 결정이나 제안을 원하면 decision-frame과 insight-report를 쓰자고 한 줄로 안내한다.

## 먼저 확인

- 질문 목록을 받는다(보통 셋 이하). 없으면 묻는다.
- `마트_설계.md`의 기준을 따른다. `산출물/3_데이터점검.md`, `3_기술비교.md`, `3_차트.md`가 있으면 그 숫자와 처리를 그대로 쓴다. 점검을 안 했으면 data-check부터 하자고 한다.

## 절차

1. **질문마다 계산한다.** 코드와 결과를 보여 주고 `산출물/코드/`에 남긴다. 이미 계산한 숫자는 다시 만들지 않고 가져온다.
2. **중요한 숫자 하나는 다른 방법으로 다시 센다.** 다르면 멈추고 보고한다.
3. **발견 문장을 쓴다.** 질문마다 한두 문장. 숫자 + 기간 + 집단 + 비교 기준. 사실만.
   - 된다: "9월 신규 고객 결제 완료율은 61.2%로 6월 79.2%보다 18.0%p 낮다"
   - 안 된다: "신규 고객이 떠나고 있다"(해석), "배송비 때문이다"(원인), "결제 화면을 고쳐야 한다"(제안)
4. **근거를 붙인다.** 발견마다 표나 차트 하나. 차트는 chart-request 기준(제목은 결론, 강조 한 곳).
5. **한계를 쓴다.** 빠진 자료, 확인 못 한 것, 다음에 물어볼 질문.
6. **제목은 결론 문장.** "9월 매출 분석"이 아니라 "9월 매출은 전월보다 3.6% 줄었고, 신규 고객의 결제 완료에서 가장 많이 줄었다".

## 출력

`산출물/3_분석리포트.md`

```markdown
# (결론 문장 제목)

## 질문
1.

## 데이터와 정의
- 파일, 기간, 처리(중복 제거 등), 지표 정의(설계서 기준)

## 발견
1. (질문 1의 답, 사실만)

## 근거
| | |
|---|---|
(차트: 산출물/차트/…)

## 한계와 다음 질문
-
- 이 리포트는 결정할 일을 묻지 않았다. 무엇을 할지는 04에서.
```

## 지킬 것

- 발견 칸에 해석, 원인, 제안을 넣지 않는다. 쓰고 싶으면 한계 칸에 "다음 질문"으로 적는다.
- 유의성은 "우연으로 보기 어렵다"까지만.
- 리포트의 숫자는 모두 코드 결과와 같아야 한다.
