# 비교 기준을 밝힌 탐색 (3단계)

## 먼저 확인

- `산출물/2_질문카드.md`를 읽는다. 없으면 어떤 질문에 답하는지 먼저 묻는다.
- `원천파일_정의서.md`와 `마트_설계.md`로 열 뜻과 지표 정의를 확인한다. 숫자를 세기 전에 집계 단위(일 · 세그먼트 · 주문)를 확인한다.
- **데이터를 먼저 점검한다.** 구조 · 결측 · 중복(같은 ID가 두 번) · 기간 경계. 발견하면 처리 방법을 사람에게 묻고, 처리 전후 숫자가 얼마나 달라지는지 보여 준다.

## 절차

1. **비교 기준을 먼저 적는다.** 목표 · 과거(지난달, 작년 같은 달) · 비교 대상(다른 집단, 채널) · 분포 중 무엇과 비교하는지. 여러 기준을 쓸 수 있으면 표 하나에 나란히 놓는다. 기준에 따라 결론이 달라지면 그 사실 자체를 결과로 적는다.
2. **나눈다.** 전체 숫자가 움직였으면 구성 요소로 분해한다(예: 매출 = 세션 × 전환율 × 객단가, 퍼널 단계별 도달률). 가장 많이 움직인 요소를 찾는다.
3. **집단별로 본다.** 결정할 일과 관계있는 기준으로만 나눈다(고객구분 · 기기 · 결제수단 · 유입경로 등). 전체 평균이 가리는 집단이 있는지 확인한다.
4. **분포를 본다.** 평균을 보고할 때는 중앙값과 구간별 비중을 함께 낸다.
5. **표본을 의심한다.** 이 자료에 빠진 사람이 누구인지 한 줄 적는다(예: 문의 게시판에는 조용히 떠난 사람이 없다).
6. 계산은 코드로 하고, 쓴 코드는 `산출물/코드/`에 남긴다. 사람이 다시 돌려 같은 숫자가 나와야 한다.

## 출력

`산출물/3_분석노트.md`의 **앞면**

```markdown
# 분석 노트 — 앞면
질문: (질문 카드의 질문)
비교 기준:

## 관찰한 사실 (누가 다시 세어도 같은 것)
- 숫자 + 기간 + 집단 + 비교 기준을 한 문장에

## 해석 (아직 검증 전)
-

## 이 자료에 빠진 것
-
```

## 지킬 것

- 사실과 해석을 한 문장에 섞지 않는다. "신규 고객이 떠나고 있다"는 해석이다. 사실은 "9월 신규 고객 결제 완료율 61%, 6월 79%".
- 원인을 여기서 확정하지 않는다. 가장 강해 보이는 설명이 있어도 해석 칸에만 적고 `rival-explanations`로 넘긴다.
- 차트는 비교가 한눈에 보이는 것 하나만 만든다(`산출물/차트/`).
