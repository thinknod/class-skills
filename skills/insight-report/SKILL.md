# 인사이트 리포트와 반론 리허설 (5단계 · 판단과 제안)

인사이트는 질문을 가지고 자료의 안을 들여다봐 기존 판단을 바꿀 이유를 찾는 일이다. 관찰한 사실(What)만 있으면 요약이고, 결정, So what, Now what까지 차야 판단을 돕는다. 설득에 성공했다고 답이 옳아지지는 않는다.

## 먼저 확인

- `산출물/1_결정할일.md`(결정권자, 기한, 선택지)와 `산출물/3_분석노트.md`(앞면 사실, 뒷면 다른 설명과 판정)를 읽는다. 03에서 만든 분석 리포트가 있으면 그것이 What이다.
- 결정할 일이 없으면 멈추고 묻는다. 결정 없이 쓰면 요약이 된다.
- 선택지가 여럿이면 영향, 비용, 위험, 근거의 확실성을 표로 비교하고 "어떤 가정이 바뀌면 순위가 바뀌는가"를 적는다. 표는 `산출물/4_우선순위.md`.

## 절차

1. **결정.** 누가, 언제까지, 무엇 중에서 고르나. 1단계 문장을 그대로 쓴다.
2. **What.** 관찰한 사실만. 분석 리포트와 노트에서 가져오고, 거기 없는 숫자는 새로 만들지 않는다. 새로 계산하면 코드를 `산출물/코드/`에 남긴다. 숫자에는 기간, 집단, 비교 기준을 붙인다.
3. **So what.** 그 결정에 이 사실이 갖는 의미. 검토한 다른 설명과 판정을 한 줄씩(왜 약한지, 무엇이 가장 강한 설명인지). "가장 강한 설명"까지만 쓰고 원인을 확정하지 않는다.
4. **Now what.** 결정권자가 예, 아니오로 답할 수 있는 요청 하나와, 언제 무엇으로 확인할지(비교집단 포함).
5. **가정과 한계.** 확인 못 한 것, 무엇이 보이면 제안을 바꾸나.
6. **제목.** 요청 문장 후보 셋을 낸다("9월 매출 분석"이 아니라 "개발 3일을 결제 오류 수정에 배정해 주십시오"처럼). 말할 수 있는 만큼만. **고르는 건 사람이다.** 고를 때까지 멈춘다.
7. **반론 리허설.** 결정권자 역할을 맡아(1단계에 적힌 상황과 제약 그대로) 반론 3개를 한다. 사용자가 답하게 한다. 답이 막히면 리포트 문장을 다듬지 말고 분석 노트로 돌아가자고 한다.

## 출력

`산출물/5_인사이트리포트.md` (요청하면 docx, pptx로도)

```markdown
# (제목 = 요청 문장. 사람이 고른 것)

| 결정 | (누가, 언제까지, 무엇 중에서) |
|---|---|

## What  관찰한 사실
-
(차트: 산출물/차트/…)

## So what  그 결정에 갖는 의미
- 가장 강한 설명:
- 검토했지만 약한 설명: (설명) - (왜 약한가)

## Now what  제안과 확인 계획
- 요청: (예, 아니오로 답할 수 있게)
- 확인: (언제, 무엇과 비교해, 무엇이 보이면)

## 가정과 한계
-

---
## 제목 후보 (사람이 고름)
1.
2.
3.

## 반론 리허설
1. 반론: / 답:
2. 반론: / 답:
3. 반론: / 답:

## 스스로 점검
- 공감: 첫 줄이 결정권자의 결정인가
- 논리: 근거에서 결론까지 가도 되나, 사실과 해석이 섞이지 않았나
- 형태: 비교가 한눈에 보이나, 한 장인가
```

## 지킬 것

- 사실, 해석, 가정, 제안을 섞지 않는다. 칸이 곧 구분이다.
- 강조 색은 말하려는 곳 한 군데. 차트는 하나.
- 내기 전 점검은 persuasion-check에 맡긴다. 이 스킬은 리포트를 쓰고 끝에 한 줄씩 스스로 점검만 한다.
