# 결정할 일 한 줄 (1단계 · 문제와 결정할 일 확인)

현상("매출이 줄었다")을 문제("운영 담당이 다음 주 개발 일정 전에 결제 화면 · 배송비 · 광고 중 무엇부터 고칠지 정한다")로 바꾼다. 분석은 아직 하지 않는다.

## 절차

1. 사용자가 준 상황을 읽고 다음 네 칸을 채운다. 모르는 칸은 추측하지 말고 비워 둔다.
   - 누가 (결정하는 사람, 역할)
   - 언제까지 (결정 시점)
   - 무엇 중에서 (선택지 2~4개)
   - 결정한다 (무엇을)
2. 빈 칸마다 사용자에게 한 번에 하나씩 묻는다. 질문은 짧게. 선택지 칸이 비어 있으면 가장 먼저 묻는다. 선택지가 없으면 분석 결과가 행동을 바꿀 수 없다.
3. 채운 뒤 숨은 가정과 빠진 맥락을 최대 3개 짚는다. 예: "광고비는 고정인가?", "개발 인원은 몇 명인가?"
4. 틀렸을 때의 비용을 한 줄 묻는다. 비용이 크면 뒤 단계에서 검증을 더 엄격히 한다.

## 출력

`산출물/1_결정할일.md`

```markdown
# 결정할 일
- 누가:
- 언제까지:
- 무엇 중에서:
- 결정한다:

한 줄: [누가] [언제까지] [무엇 중에서] [무엇을] 결정한다.

## 숨은 가정 · 빠진 맥락
-
## 틀렸을 때의 비용
-
```

## 지킬 것

- 어떤 문제를 다룰지는 사람이 정한다. 여러 역할의 문제가 섞여 있으면 하나를 골라 달라고 한다.
- 이 단계에서 데이터를 열어 결론을 내지 않는다. 데이터는 선택지를 확인하는 정도로만 본다.
