# 결정과 이어진 대시보드 한 장 (6단계)

대시보드는 같은 질문을 계속 보는 한 화면이다. 매출, 전환율, 객단가를 늘 같은 자리에 두면 다 맞는 숫자지만 어떤 결정도 기다리지 않는다. 그래서 이 스킬은 숫자가 아니라 **인사이트 리포트의 확인 계획**에서 시작한다.

## 먼저 확인

- `산출물/5_인사이트리포트.md`의 결정과 Now what을 읽는다. 없으면 "이 화면이 돕는 결정"과 "어디까지 오면 무엇을 할지"를 먼저 묻는다. 결정 없이 만들면 아무도 열지 않는 화면이 된다.
- 누가, 얼마나 자주(매주 월요일 등) 여는 화면인지 받는다.

## 절차

1. **결정 한 줄**을 맨 위에 쓴다. 예: "결제 오류 수정이 신규 완료율을 되돌렸나. 안 되면 배송비 재검토".
2. **KPI 셋을 Now what에서 고른다.** 결정이 맞았는지 알려 줄 숫자. 각 KPI에 기준선(비교 기간이나 비교집단)을 붙인다. 셋을 고른 이유를 한 줄씩 적고, 사람이 바꾸고 싶으면 바꾼다.
3. **숫자는 코드로 만든다.** `산출물/코드/대시보드_숫자.py`가 주제별 표에서 KPI, 추세, 비교를 계산해 `산출물/코드/대시보드_숫자.json`에 쓴다. 리포트에 이미 있는 숫자는 같은 정의로 다시 계산해 리포트와 같은지 본다. 데이터에 없는 추이(예: 일별)는 만들어 넣지 않는다.
4. **화면을 만든다.** `assets/template.html`을 복사해 `산출물/6_대시보드.html`로. 위에서 아래로 결정 → KPI 셋 → 추세와 기준선 → 비교 → 다음 기준과 출처. 외부 라이브러리 없이 한 파일로 연다.
   - 차트 제목은 결론 문장. 강조색은 한 곳. 막대는 0에서.
   - 화면의 숫자는 json의 값을 그대로 옮긴다(반올림 자리만 맞춘다).
5. **대조한다.**
   ```bash
   python3 <이 스킬 폴더>/scripts/verify_dashboard.py 산출물/6_대시보드.html 산출물/코드/대시보드_숫자.json
   ```
   화면에 있는데 json에 없는 숫자, json의 KPI인데 화면에 없는 숫자를 보여 준다. 0개가 될 때까지 고친다. 남는 것이 있으면 이유를 적는다(예: 날짜).
6. **비평은 새 대화창에.** "이 대시보드가 결정 한 줄에 답하나, 질문, 데이터, 화면이 맞나"를 새 대화창에서 받아 보라고 안내한다.

## 출력

`산출물/6_대시보드.html`, `산출물/코드/대시보드_숫자.py`, `산출물/코드/대시보드_숫자.json`, 그리고 `산출물/6_대시보드.md`

```markdown
# 대시보드: (결정 한 줄)
여는 사람, 주기:
| KPI | 값 | 기준선 | 고른 이유 (Now what의 어느 문장) |
|---|---|---|---|
대조: verify_dashboard 결과 (화면에만 있는 숫자 0개, 빠진 KPI 0개)
다음 기준: (어디까지 오면 무엇을 하나)
```

## 지킬 것

- 결정 한 줄이 없으면 만들지 않는다.
- KPI는 셋. 더 넣고 싶으면 무엇을 뺄지 사람에게 묻는다.
- 필터는 기간 하나부터. 화면 하나에 비교 하나.
- 숫자를 손으로 옮기지 않는다. json → 화면, 그리고 대조.
